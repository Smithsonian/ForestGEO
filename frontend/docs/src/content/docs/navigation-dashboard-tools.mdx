The sidebar and dashboard are your primary interfaces for navigating the ForestGEO application. This guide explains how to use them effectively.

---

## The Sidebar

The sidebar is located on the left side of the screen and contains all navigation elements. It is divided into two main areas:

1. **Selection Dropdowns** - Site, Plot, and Census selection
2. **Navigation Menu** - Links to all application features

### Selection Dropdowns

Before you can access most features, you must make selections in the sidebar dropdowns. These selections determine which data you're working with.

#### Site Selection

The **Site** dropdown is the first selection you'll make after logging in.

:::note
Sites represent geographic locations where forest plots are established. You will only see sites that an administrator has assigned to your account.
:::

When you select a site, the application connects to that site's database schema. All subsequent data operations will apply to the selected site.

#### Plot Selection

After selecting a site, the **Plot** dropdown becomes available.

A plot is a specific geographic region within a site where data collection occurs. Plots have defined dimensions, coordinates, and are subdivided into quadrats.

:::tip
If a plot is missing its dimensions or coordinates, click the **pencil icon** on that plot's card in the plots overview to open the plot editor. Coordinates and units feed the validations, so change them deliberately.
:::

#### Census Selection

After selecting a plot, the **Census** dropdown appears.

A census represents a time period during which measurements were collected. Each census has:

- **Start date** - When data collection began
- **End date** - When data collection completed
- **Census number** - Sequential identifier (Census 1, Census 2, etc.)

In the dropdown these appear as **First Msmt** and **Last Msmt**, because the app shows the range
your measurements actually span rather than the dates typed in at creation.

:::note
**Census Hub** stays disabled until you select a census. **Stem & Plot Details** does not — it
becomes available as soon as you have a site and a plot, which is what lets you set up species,
quadrats and stem codes before any census exists. Destinations you cannot reach yet are shown
greyed out rather than hidden.
:::

## Navigation Menu

Once you've selected a site, plot, and census, the navigation menu becomes active. It is organized into the following sections:

### Dashboard

The home page showing census statistics and data health metrics. See the [Dashboard](#the-dashboard) section below for details.

### Stem & Plot Details

This section contains the supporting reference data that measurements point at.

| Page             | Description                                                                           | Required first? |
| ---------------- | ------------------------------------------------------------------------------------- | --------------- |
| **Stem Codes**   | Attribute codes describing tree/stem conditions (e.g., "D" for dead, "L" for leaning) | **Yes**         |
| **Species List** | Inventory of all species found in the plot with taxonomy information                  | **Yes**         |
| **Quadrats**     | Geographic subdivisions of the plot                                                   | **Yes**         |
| **Personnel**    | Field staff and data collection team members for the census                           | No              |

:::caution
Stem Codes, Species List and Quadrats must each hold at least one record before you can upload
measurements. **Personnel are not part of that gate** — worth filling in to record who collected
the data, but an empty personnel list will not block an upload.
:::

### Census Hub

This section contains interfaces for working with measurement data and census analysis.

| Page                         | Description                                                 |
| ---------------------------- | ----------------------------------------------------------- |
| **Census Overview**          | Summary of the selected census: tree and stem counts, quadrat coverage, errors and an export preview. Publish or delete the census from here |
| **View Data** | View, sort, filter and edit every measurement in the current census. **Show** (All, Passed, Pending, With errors) and **Search** narrow the grid, the **Validation** column states each row's validation result, and **Details** opens a side sheet for the row |
| **View Errors** | Every unresolved error in the census, grouped by type, with census totals and a details sheet per row |
| **Post-Census Statistics**   | Run statistical analyses on your census data                |
| **Recent Changes**           | Audit trail showing all data modifications                  |
| **Uploaded Files**           | History of files uploaded to the system with download links |
| **View All Historical Data** | Browse measurements across all censuses                     |
| **Validations**              | Configure and manage data validation rules                  |

#### The Census Overview page

The header shows the site and plot, the census number and its date range. On the right are
**Publish census** and a **⋯** menu with **Rebuild ViewFullTable** and **Delete census**. Only the
latest census can be deleted; when deletion isn't allowed, the menu says why.

If anything would stop a publish, a red callout under the header names each problem, how many rows
it affects and how to fix it.

Below that, the page has these sections, from top to bottom:

- **Census totals** - four tiles:
  - **Trees** - how many trees were measured, the average number of stems per tree and how many
    trees have more than one stem.
  - **Stems** - how many stems were measured, how many were **previously measured** (their tree tag
    and stem tag were both in the previous census) and how many are **new recruits** (stems on
    trees the previous census didn't have). Hover over either count to see its definition. These
    counts don't add up to the stem total. The dashboard calls previously measured stems
    **Old Trees**. On a first census there is nothing to compare against, so the tile says
    **no previous census**.
  - **Quadrats with data** - how many of the plot's quadrats have measurements, and how many are
    not yet measured.
  - **Measurements with errors** - how many active measurements have unresolved errors.
- **Validation Errors** - the number of measurements with unresolved errors, then a table of the
  five most common error types with their row counts and their share of all active measurements.
  One measurement can have several errors, so the shares can add up to more than the total. Click
  an error type to open **View Errors** filtered to it, or **View all errors** to see every one.
- **If you publish now** - how many measurements a publish would send to the Smithsonian database
  and how many it would skip, with the reasons for skipping. One row can be skipped for more than
  one reason. If any exported rows still have an unresolved error, the panel says how many.
- **Data Quality** - results of the post-census statistics queries, with a button to run them again.

The other Census Hub pages are in the sidebar.

### Administration (global role)

The administration tools are reached from the **gear icon at the bottom of the sidebar**, next to
your name — not from the main navigation menu. Its menu offers **User Settings**, **Site
Settings**, **User-Site Assignments** and **Provisioning**.

:::note
The sidebar only grows an Administration section once you are already on an admin page, so if you
are looking for it on the dashboard you will not find it. Start from the gear icon.
:::

Once you are in that section, the sidebar lists:

| Page                       | Description                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------ |
| **Users**                  | Manage user accounts and their roles                                                 |
| **Sites**                  | Catalog of all sites the app knows about                                             |
| **Assignments**            | Grant or revoke site access for individual users                                     |
| **Provisioning**           | Stand up a brand-new site, plot, census, and quadrat grid through a 4-step wizard. See [Site Provisioning](/ForestGEO/admin/site-provisioning/) |
| **Provisioning runs**      | History and status of every provisioning attempt                                     |

## The Dashboard

The dashboard provides an at-a-glance overview of your census progress and data health.

### Visual conventions (updated May 2026)

- **Clickable site & plot cards.** The overview cards on the dashboard are now active — click a site card to jump straight into that site's plot view; click a plot card to jump into its census view. The dropdown selectors still work the same way; cards are a faster path.
- **Top loading bar instead of a modal.** Routine reads (loading a list, switching plots) show a slim progress bar at the top of the page instead of blocking the screen with a modal overlay.
- **Skeleton loaders.** Cards and tables now render shaded placeholders while data streams in, so the page lays out immediately rather than appearing blank.
- **Prefetched navigation.** The sidebar quietly prefetches likely-next pages, so most navigation feels instant.
- **Auto-refresh.** Data grids and dashboard cards refresh themselves after edits, deletes, and reingestion — you no longer need to reload the page to see your changes.

### Census Progress Metrics

The dashboard displays visual indicators showing:

- **Total stems measured** - How many stems have been recorded
- **Validation status** - How many records have passed validation
- **Data completeness** - Progress toward census completion

### Stem Statistics

Key statistics about your census data:

| Metric           | Description                                          |
| ---------------- | ---------------------------------------------------- |
| **Old Trees**    | Stems (not trees) whose tree tag and stem tag were both in the previous census |
| **Multi-Stems**  | Trees with more than one stem                        |
| **New Recruits** | Stems on trees the previous census didn't have       |

:::note
Despite its name, **Old Trees** counts stems. On the Census Overview page the same number is
labelled **Previously measured stems**. On a first census it shows a dash, because there is no
previous census to compare against.
:::

### Data Validity Status

The dashboard shows whether your supporting data is ready:

- ✓ **Green checkmark** - Data is present and valid
- ✗ **Red indicator** - Missing required data
- ! **Warning badge** - Data needs attention

:::note
If you see warning indicators in the sidebar navigation, it means one or more data types in that section are missing required data.
:::

### Recent Changes

A quick view of the most recent data modifications, showing:

- What was changed
- Who made the change
- When it occurred

Click **Recent Changes** in the Census Hub to see the full audit trail.

### Exporting the change log

On the **Recent Changes** page, **Export CSV** downloads the changes you are looking at as a spreadsheet file. The export uses the filters on the page: the preset, **Changed By**, **Table**, **Quick Search** and the **From (UTC)** / **To (UTC)** dates. The export covers the site and plot you have selected. To continue from an earlier export, set **From (UTC)** to the day of that export: the day is included, so its changes appear again, and the `LogID` shows which ones you already have.

The file follows the layout of the CTFSWeb `Log` table. It lists one row for each changed field, plus summary rows for uploads, bulk revisions and similar changes, oldest change first.

| Column          | What it holds                                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `LogID`         | The number of the change. Every row of one change repeats it, so it identifies the change, not the row.                     |
| `ChangedBy`     | The account that made the change. Blank when none was recorded.                                                             |
| `ChangedTable`  | The table that changed, such as `trees`, `stems`, `species` or `coremeasurements` (measurements).                           |
| `PrimaryKey`    | The key of the changed record. For an upload summary, the file name.                                                        |
| `ChangedColumn` | The field that changed. `*` marks a summary row that does not name one field.                                               |
| `ChangeDate`    | The day of the change.                                                                                                      |
| `ChangeTime`    | The day and time of the change.                                                                                             |
| `Description`   | A short sentence describing the change, written by the application.                                                         |
| `Action`        | `I` for an added record, `U` for an update, `D` for a deletion.                                                             |
| `Old`           | The value before the change. Blank for an added record and for summary rows.                                                |
| `New`           | The value after the change. Blank for a deleted record and for summary rows.                                                |
| `PlotID`        | The plot the change was recorded for. Blank means no plot was recorded, as for species and other site-wide data, and for measurements entered or deleted by hand in the data grid. These rows are included in the export for your plot.            |
| `CensusID`      | The census the change was recorded for, when there is one.                                                                  |

**Finding a change on screen.** A card for a single change shows its number in the header, for example `#4821`. A grouped upload card ("N rows uploaded") shows the numbers only after you select **Show uploaded records**. The `LogID` of an upload summary row is the number of the first change in that upload group. Type `#4821` into **Quick Search** to find the change behind a `LogID`. A bare `4821` finds it too, but also finds every change whose text contains 4821, so the `#` form is the precise one.

**Choosing the dates.** **From (UTC)** and **To (UTC)** accept dates from 1000-01-01 to 9998-12-31, and the **To (UTC)** day is included in full. **Export CSV** stays disabled while the range is not valid, that is, when **From (UTC)** is after **To (UTC)** or a date is outside those limits. The page shows a message under the dates.

**Measurement uploads are summarized.** A measurement upload can write many thousands of rows, so the export does not list them one by one. Each upload appears as summary rows: one for the file itself, which holds the file name or a reference to it in `PrimaryKey`, and one row each for the measurements it added, updated and removed, so up to three more, with the count in the `Description`. Removed measurements are listed under the file they were originally loaded from, not under the upload that removed them. Measurements whose original file was not recorded are grouped under `(no file recorded)` in `PrimaryKey`. Measurements you enter or delete by hand in the data grid are listed field by field.

**Other uploads.** Species, stem code and personnel uploads are listed field by field, exactly like edits made by hand, because the application cannot tell the two apart afterwards. The taxonomy (family and genus), role and census roster changes they cause are listed the same way. A large upload of this kind makes a large export. A quadrat upload appears only as its file summary row, plus one acknowledgment row when overlapping quadrats were acknowledged.

**What is not exported.** An update whose recorded before and after values show no visible difference has a card on the page and no row in the file.

**Older changes.** Some edits recorded before March 2026, by the older change log, may show their old and new values as separate entries instead of one side-by-side change. This happens both on screen and in the file.

**Species and quadrat names.** When a changed field refers to a species or a quadrat, for example a tree's species, `Old` and `New` hold the stored ID numbers and the `Description` adds the code or name, for example `(abcdsp -> abcdef)`. This does not apply to changes of the species or quadrat lists themselves. The names are the ones in use today: if a species was renamed after the change, the description shows the new name. If a name cannot be found, the stored number stays.

**Row limit.** One export holds at most 50,000 rows. If yours is larger, the page tells you; narrow the date range or pick one table and export again.

**Time zone.** Dates and times in the file, and the **From (UTC)** and **To (UTC)** filters, are in UTC. Cards show relative times such as "2 hours ago"; hover over one to see the full date and time, which uses your computer's time zone, so the two can differ.

**While an export runs.** The button shows a spinner until the file downloads. If you switch to another site or plot meanwhile, the export is cancelled and no file is saved.

## Understanding Data Dependencies

The application enforces a specific workflow to ensure data integrity:

```
Step 1: Select Site → Plot → Census
              ↓
Step 2: Add supporting data (Stem Codes, Species, Quadrats)
              ↓
Step 3: Upload/Enter Measurements
              ↓
Step 4: Run Validations & Statistics
```

### Why Fixed Data Comes First

Measurements reference Fixed Data records. When you upload a measurement file:

- **Species codes** must exist in the Species List
- **Quadrat names** must be defined in Quadrats
- **Attribute codes** must exist in Stem Codes
- **Personnel** should be recorded for the census

If these references don't exist, measurements will fail validation. They are **not lost** — failed rows are written into the main `coremeasurements` table with `StemGUID = NULL` so you can review and reingest them once the reference data is in place. See [Failed Measurements Guide](/ForestGEO/errors/failed-measurements-guide/).

## Tips for Efficient Navigation

1. **Use the sidebar wisely** - Always verify your Site/Plot/Census selection before making changes
2. **Check the warning badges** - A red badge indicates missing data that needs attention
3. **Complete Fixed Data first** - This unlocks the View Data page and prevents upload failures
4. **Bookmark the dashboard** - Return here regularly to check your census progress
5. **Review Recent Changes** - Monitor the audit trail to track all modifications
