# Git Hooks

Shared Git hooks for the ForestGEO project. `core.hooksPath` points here, so these
run in the main checkout **and in every worktree** — the path is relative, so git
resolves it against whichever worktree is committing.

Setup is automatic: `npm install` in `frontend/` runs the `prepare` script, which
sets `core.hooksPath` for you. To do it by hand:

```bash
git config core.hooksPath .githooks
```

> Previously husky owned `core.hooksPath` (`frontend/.husky/_`). That directory is
> generated by `npm install` and therefore existed only in the checkout where npm
> had run, so **no hook fired in any worktree** and the pre-push gate below never
> ran at all. husky has been removed; git does this natively.

## Pre-Commit Hook

`pre-commit` refuses to commit anything under a `superpowers/` path — those are
local-only working documents kept in `~/dev/ForestGEO-local` (see the root
`CLAUDE.md`). It inspects the STAGED file list, so `git add -f` is caught too;
deletions are exempt so the paths can still be untracked. It then runs
`lint-staged`, skipping that step in a worktree where `npm install` has not run
rather than fetching lint-staged from the registry mid-commit.

## Pre-Push Hook

The `pre-push` hook automatically runs tests before allowing pushes to protected branches (`main` and `forestgeo-app-development`).

### Features

- Runs all frontend tests before pushing to `main` or `forestgeo-app-development` branches
- Aborts the push if any tests fail
- Only runs for protected branches (other branches push normally)

### How It Works

1. When you push to `main` or `forestgeo-app-development`, the hook detects the branch name
2. It runs `npm test` in the `frontend` directory
3. If tests fail, the push is aborted with an error message
4. If tests pass, the push continues normally

### Bypassing the Hook

In rare cases where you need to bypass the hook (not recommended):

```bash
git push --no-verify
```

**Warning:** Only use this if absolutely necessary and you understand the implications.

### Troubleshooting

**Hook not running:**
- Verify the hook is executable: `ls -l .githooks/pre-push` (should show `-rwxr-xr-x`)
- Check your Git hooks path: `git config core.hooksPath`

**Tests failing:**
- Run tests locally first: `cd frontend && npm test`
- Fix any failing tests before attempting to push
- Ensure all dependencies are installed: `cd frontend && npm install`
